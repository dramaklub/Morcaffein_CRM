MORCAFFEIN CRM — DESIGNER / STRUCTURAL UI BUNDLE (DELTA)
Dated snapshot: 2026-09-19 (third pass today — supersedes the previous same-dated
file, which covered the Admin "Manage Users" tab. This pass covers the Manager
"Campaign" tab and the Admin "Approvals" tab, both newly built and wired in since
then).
Only structural UI files new or changed since the previous ai-context-designer-
bundle.txt are listed here. Everything not mentioned — TransactionView, CartLine
Control, the Feedback/Customer drawer boxing, and everything documented in the
prior 2026-09-19 designer pass (ManageUsersView, PaginationControl, PlaceholderView)
is still current and unchanged.

Context for this delta: FrmMain now wires real views into two of the three
remaining placeholder slots:
  - Manager "Campaign" tab  -> CampaignManagementView (was PlaceholderView)
  - Admin   "Approvals" tab -> ApprovalsView            (was PlaceholderView)
Only "Dashboard" (Manager and Admin) is still a PlaceholderView. Also note two
dialogs from the previous designer pass are GONE — FrmEditEmployee.cs and
FrmResetPassword.cs were deleted outright (no remaining references anywhere in
the codebase; build is clean without them), so ManageUsersView's Edit/Reset-
Password actions currently have no modal behind them — flag this to confirm
whether that's mid-refactor or an intentional temporary state.

Files new this session:

  ----- Manager: Campaign tab -----

  - CRM_Morcaffein/Views/Controls/CampaignManagementView.cs
      New. No .Designer.cs; layout is in code. Structure mirrors TransactionView's
      product-grid area rather than the Customer/Feedback drawer pattern — there
      is NO drawer here, just a card grid:
        * Standard cardOuterPanel(Padding 24) > tableCardPanel(FixedSingle) shell.
        * Header (Height 60): search TextBox (300x28, "Search by name or
          category") debounced via a 200ms System.Windows.Forms.Timer so the grid
          only rebuilds after the user pauses typing (filtering is client-side
          against the in-memory _allCampaigns list, not a re-fetch); a right-
          docked-by-resize-handler "+ New Campaign" button (170x32) opens
          FrmCampaignDetail.ForCreate(...). 1px bottom divider.
        * Card area: the exact "AutoScroll wrapper Panel + absolutely-positioned,
          Dock=None TableLayoutPanel whose Width is synced on host resize" pattern
          TransactionView uses for its drinks grid. 4 columns, each card
          260x200 with 8px margins (216px row height including margins). A
          trailing 100%-height spacer row absorbs leftover space so the last row
          of cards doesn't stretch. An empty-state label ("No campaigns yet...")
          spans all 4 columns when the filtered list is empty.
        * Each cell is a CampaignCardControl; its CardClicked event opens
          FrmCampaignDetail.ForView(controller, campaign). Both create and view
          flows show a Toast.Show(...) confirmation and reload the grid on
          DialogResult.OK.
        * View is Manager-only per its own doc-comment — Baristas never see the
          tab, and Admin's campaign oversight goes through Approvals instead.

  - CRM_Morcaffein/Views/Controls/CampaignCardControl.cs
      New. Self-painted Panel (OnPaint only, no children) — same convention as
      ProductCardControl. 260x200, 12px padding. Stacked regions top-to-bottom:
      campaign name (bold 11f, up to 2 lines via a LineLimit+Ellipsis
      StringFormat, 40px), category (muted 8.5f, 20px), discount summary (bold
      13f, brand color, 28px), date range (muted 8.5f, 20px), then a status pill
      anchored to the card's bottom (24px). Whole tile is one click target — no
      interactive sub-regions, unlike ProductCardControl's per-size quick-add
      buttons. Hover swaps BackColor to Tint90, same as the other card controls.

  - CRM_Morcaffein/Views/FrmCampaignDetail.cs
      New, large (895 lines) modal — full source in today's ai-context-bundle.txt
      FILE context. Exposes two static factories used by CampaignManagementView:
      ForCreate(controller) and ForView(controller, campaign). Not yet walked
      field-by-field in this bundle; flagged for a follow-up pass if pixel-level
      review of its form layout is needed. Handles both the create flow and the
      existing-campaign activate/deactivate/edit flow in one form.

  ----- Admin: Approvals tab -----

  - CRM_Morcaffein/Views/Controls/ApprovalsView.cs
      New (681 lines). Unlike CampaignManagementView, THIS one does use the
      card-list-plus-left-drawer pattern (same family as CustomerManagementView /
      FeedbackManagementView), but with the roles of "list" and "drawer" swapped
      left/right relative to those two views — here the drawer describes it as
      appearing after cards are on the right, cards a vertical list not a grid:
        * Right side: cardOuter(Padding 24) > card(FixedSingle) shell. Header
          (Height 76) holds a two-line title block — "Pending Campaign Approvals"
          (bold 13f) above a _countLabel (regular 9f, muted, shows the live
          pending count) — with a 1px bottom divider.
        * Cards area: a FlowLayoutPanel (_cardsFlow) inside an AutoScroll
          Panel(_cardsScrollHost), TopDown, one ApprovalCardControl per pending
          campaign, each 72px tall with an 8px bottom gap (CardGap). An
          _emptyStateLabel covers the "nothing pending" case.
        * Left drawer (DrawerWidth 420): _drawerEmptyLabel swaps with
          _drawerContentPanel once a card is clicked. Drawer content is built from
          two fixed-size bordered boxes stacked in a flow — _detailBoxPanel
          (340x400) holding campaign name/meta plus a full field dump (category,
          discount, target tier, min purchase, max discount, max redemptions,
          start/end dates, creator, requested-at — each its own Label on a
          DetailRowSpacing=28 grid), and a separate _decisionPanel (340x200) below
          it holding a decision-notes TextBox, an error Label, and Approve/Reject
          buttons.
        * Approve/Reject call into CampaignController against the
          GET /campaigns/pending-backed dataset; Reject requires the notes field
          (used as the rejection reason) — enforced client-side via
          _decisionErrorLabel before the request is sent.
        * Admin-only per its own doc-comment; FrmMain wires it in place of the
          Approvals placeholder for the Admin nav only.

  - CRM_Morcaffein/Views/Controls/ApprovalCardControl.cs
      New. Self-painted Panel, same convention as CampaignCardControl. 72px tall,
      full row width, 8px bottom margin (no side margins — it's a list row, not a
      grid cell). Two text lines: line 1 (y=14, 24px) is promo name (bold) +
      category (muted) + discount (bold, brand color) left-to-right; line 2
      (y=40, 20px) is "date range · by Creator" (muted, small) on the left with a
      status pill drawn flush right, using the identical pill fill/text scheme as
      CampaignCardControl so the two surfaces read as one system.

  ----- Shared: new lightweight UI utility -----

  - CRM_Morcaffein/Views/Controls/Toast.cs
      New static helper, not a reusable control instance — Toast.Show(host,
      message, ToastKind). Renders a borderless, self-sizing Panel+Label
      (min 260 / max 460 wide, 40px tall, text measured to fit) bottom-center of
      the toast's HOST FORM (deliberately re-parented up to FindForm(), not the
      passed-in control — added directly to a UserControl it could land as a
      sibling of that view's own card panel and render underneath the pagination
      bar, since BringToFront only reorders within one parent). Multiple toasts
      stack upward via a Tag-based sibling count. Holds 2.4s then is hard-removed
      — no fade animation; WinForms can't cheaply fade a child control, and a
      manual color-lerp would leave a visible trail against a differently-colored
      host background. ToastKind.Success/Info/Error map to
      BrandPalette.StatusPositiveFill/SurfaceCard/StatusNegativeFill. Used so far
      by CampaignManagementView's create/edit confirmations.
